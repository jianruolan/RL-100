## 4. 高频推理脚本对比

`infer_piper_control_clean_dp3.py` 的时钟是解耦的：

```text
相机约15 Hz
→ 异步策略推理，受相机和GPU吞吐限制
→ 最新 action chunk[0] 更新 active_target
→ 100 Hz 规划、反馈读取和 Piper 命令下发
```

因此它实现的是高频控制和下发，不是 100 Hz 完整 DP3 推理。`--policy-rate 0` 时，策略请求由新相机帧触发；设置高于相机频率只会重复使用旧观测，不能产生等价的新视觉信息。

smooth 脚本更强调轨迹平滑和开合时序：

- Temporal Ensemble 融合重叠 action chunk；
- jerk-limited planner 限制速度、加速度和 jerk；
- GripperPoseCoordinator 对夹爪切换进行去抖、姿态等待和切换后保持；
- 控制频率通常与 `--rate` 绑定。

高频 control-clean 更适合分析“模型延迟”和“执行滞后”是否分离；smooth 更适合在已有策略输出后抑制动作抖动，但额外门控可能增加夹爪等待时间。

## 5. 今日经验与下一步

1. 评价模型时必须同时固定推理脚本、控制频率、planner tracking error、速度限制和夹爪门控，否则模型差异会被执行层掩盖。
2. milestone50/75 的抓取问题需要记录原始第 7 维策略输出和实际夹爪反馈，不能只看机械臂是否到达空间位置。
3. 放置阶段优先使用 control-clean 做 tracking error A/B，记录重同步次数、目标误差和到达时间。
4. release3 medium 训练结束后，使用 milestone75、best_val 和最终 BC 权重做同一初始状态的真机对照。
5. 新增的 Zarr 裁剪选项和 control-clean 依赖文件应作为同一代码提交，避免入口脚本在干净环境中缺少 `JointTrajectoryPlanner`。
