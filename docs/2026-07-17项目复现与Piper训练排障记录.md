## 4. 训练阶段和实际执行条件

RL-100 主流程可概括为：

```text
BC policy
→ Q/Value critic
→ learned dynamics
→ BPPO/Uni-O4 offline RL
→ 可选真机 online RL
```

关键配置：

```yaml
training.resume: 是否加载已有 policy checkpoint
offline: 是否训练 dynamics 并进入 offline policy finetune
online: 是否进入环境交互和 online RL
```

`offline=False` 时，程序在 Q/Value 后结束是预期行为：dynamics 对象可能被创建，但不会执行 `dynamics.learn()`，也不会进入 `finetune_dp3()`。

另外，当前代码中的 `only_bc=True` 并不会阻止后续 critic 初始化和训练，不能把它理解为“BC 完成后立即退出”。

## 6. Action chunk 与 dynamics 配置

曾出现：

```text
chunk_as_single_action=True requires dynamics.prediction_mode='full'
```

现有 Q/Value 是按 `chunk_as_single_action=True` 创建的。为了兼容已有 critic 权重，续训时保持：

```yaml
chunk_as_single_action: true
dynamics.prediction_mode: full
```

不要在复用已有 Q/Value 时随意切换为 `chunk_as_single_action=False`，否则 critic 输入结构可能不一致。

## 7. 无 env runner 的 offline RL

Offline RL 训练本身不要求连接真机，但原 `finetune_dp3()` 会调用：

```python
self.eval()
env_runner.run()
```

这属于环境评估，不是 offline 参数更新的必要条件。当前代码已在 `env_runner is None` 时：

- 跳过真实环境 policy evaluation；
- 跳过 IDQL 环境评估；
- 跳过 EMA 环境评估；
- 不调用 `env_runner.run()`；
- 保留 Q、dynamics 和 BPPO/Uni-O4 更新；
- 使用 dynamics rollout 的 `current_mean_qs` 做临时离线策略选择。

`current_mean_qs` 是 learned dynamics 与 learned Q 给出的模型内估计，不是真实成功率。只有 8 条低质量 episode 时，它可能受模型误差和 Q 高估影响，只适合 smoke test，不应直接证明真机性能提升。

```text

```

若 `current_mean_qs` 上升而 `dynamics_val_loss` 同时恶化，应警惕 policy 利用 dynamics 模型误差。

## 10. 后续真机 runner 参考

纯 offline RL 可以没有 runner；真机 online RL 必须实现 Piper 环境交互。推荐参考：

- `env_runner/rotate_runner.py`：只推理和真机评估循环；
- `env/ur5/UR5_env.py`：单臂六轴 + RealSense 的环境结构；
- `env_runner/flipping_runner.py`：较完整的真机任务 runner；
- `gym_util/multistep_wrapper_real.py`：`step_online()` 与 action chunk；
- `train_real.py`：真机 online replay 和策略更新。

建议新建 `PiperEnv + PiperRunner`，不要直接复用 AdroitRunner。真机上线前必须完成动作单位确认、关节/速度限制、急停、reset、接触 reward、timeout 和相机预处理一致性验证。
