## 4. chunk-4 控制策略组合实验

### 4.1 trajectory smoothing

记录：

```text
pick_place_control_clean_epoch4000_smooth_execute_01.json ... _07.json
```

共同设置以 15 Hz 为主，并启用轨迹平滑。常用上限为 0.35 rad/s、0.8 rad/s²、
4.0 rad/s³、response 2.0；speed percent 比较了 10、15 和 100。`_06` 是较长的一次运行，
记录 8000 step / 533.3 s，以 `max_steps` 结束，并使用 0.55 rad/s、response 3.0。
其他多由操作员 hold 停止。该组用于观察限速、加速度和 jerk 约束对抖动、响应和过冲的影响，
日志本身不能给出任务成功结论。

### 4.2 smoothing + temporal ensemble

记录：

```text
pick_place_control_clean_epoch4000_smooth_temporal_execute_01.json ... _04.json
```

前三项以 15 Hz 控制/15 Hz 相机运行，`_04` 提高到 20 Hz 控制/30 Hz 相机。这一阶段还没有
启用 gripper pose-sync。日志中新的策略结果常只有约 4.8--5 Hz，`_04` 约 4 Hz；说明
temporal ensemble 能融合旧预测、减轻 chunk 边界观感，却不能提高模型原始推理吞吐。

### 4.3 smoothing + temporal ensemble + gripper pose-sync

记录：

```text
pick_place_control_clean_epoch4000_smooth_temporal_pose_sync_execute_01.json ... _02.json
pick_place_chunk4_epoch4000_smooth_temporal_pose_sync_execute_03.json ... _06.json
```

这些实验通常使用 15 Hz、speed 10、0.35 rad/s、0.8 rad/s²、4.0 rad/s³ 和 response 2.0；
`_06` 使用 speed 100。pose tolerance 约 0.025 rad，stable steps 为 2 或 3，并测试了
transition hold。`_05` 记录 5706 step / 380.3 s，`_06` 为 2649 step / 176.5 s，主要由
操作员 hold 结束。该组合的目标是让夹爪切换与稳定手臂姿态对齐，减少动作阶段冲突。

## 8. 70.79M 模型的 Thor 性能诊断

原 chunk-4 模型总计 70.7876M 参数，其中 UNet 为 70.7238M。真实 Zarr 观测、EMA 权重、
CUDA 同步后的纯策略测试为：

| DDIM steps | 平均耗时 | 纯推理频率 |
| ---: | ---: | ---: |
| 10 | 132--134 ms | 7.4--7.6 Hz |
| 5 | 67.0 ms | 14.9 Hz |
| 3 | 41.5 ms | 24.1 Hz |
| 1 | 16.1 ms | 62.1 Hz |

FP16 autocast 实测约 157 ms，反而更慢。结论是 10-step、70.79M 模型本身就无法满足
15 Hz 的 66.7 ms 总预算；这与真实执行日志一致。更完整的性能、planner 限速和排障分析见
同日《Piper DP3 真机推理性能与排障记录》。

| 标签 | `down_dims` | time embed | 参数量 | Thor 10-step |
| --- | --- | ---: | ---: | ---: |
| 原模型 | `[256,512,1024]` | 256 | 70.79M | 133.1 ms / 7.5 Hz |
| medium | `[128,256,512]` | 128 | 19.14M | 63.5 ms / 15.7 Hz |

tiny64 验证更小容量的下限，再运行 medium 作为容量回退对照。

## 12. 后续对比规则

训练完成后对原模型、small96 和 tiny64 使用同一批初始姿态、物体位置、光照和 planner
限制，至少记录：

1. 抓取、搬运、放置三个阶段的人工成功标签及完整成功率；
2. 完成时间、震荡、停滞和过冲次数；
3. P50/P95 inference latency、新 chunk 完成 Hz 和 policy age；
4. 控制 loop Hz、真实关节速度和 gripper 切换时刻；
5. 相同 10-step 设置比较容量后，再对入选模型做 10/5/3-step A/B。

若 tiny64 的人工任务结果接近 small96，可优先更小模型；若 tiny64 明显退化，优先 small96；
medium 则作为已排队的容量回退对照。小模型达到更高策略频率也不等于机械臂自动变快，
物理速度仍由 planner 和 Piper speed percent 共同限制。
