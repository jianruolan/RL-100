## 2. Piper 3D固定训练脚本

文件：

```text
scripts/Diffusion/Offline/3D/train_policy_piper_soft_block.sh
```

脚本支持以下环境变量：

```text
GPU_ID
OFFLINE
RESUME
RUN_DIR
DATASET_PATH
DISTILL_PHASE
N_OBS_STEPS
ACTION_STEPS
HORIZON
```

其中：

```text
DISTILL_PHASE=null|after_dp|after_offline
```

用于选择不蒸馏、BC蒸馏或offline best蒸馏。

当前脚本对chunk参数进行了校验。Piper脚本固定使用`n_obs_steps=3`作为默认值，因此必须满足：

```text
horizon = n_obs_steps + n_action_steps - 1
```

例如chunk4应为：

```yaml
n_obs_steps: 3
n_action_steps: 4
horizon: 6
no_pre_action: true
```


训练顺序：

```text

```

如果只想训练chunk4而不做BC蒸馏，将`DISTILL_PHASE=after_dp`改为：



## 7. 当前已知问题

### 7.1 resume逻辑不能正确续接未完成BC

`latest.ckpt`存在时，当前`train.py`会倾向于跳过BC阶段。因此如果BC只训练到epoch100就中断，直接设置`RESUME=True`可能会把它当作BC已完成，直接进入Q/Value。

已检查的`piper_soft_block_contact_2d_50_seed42`实验中：

```text
latest.ckpt: epoch=100, global_step=8988
```

它可以读取，但当前代码不保证从epoch100继续到epoch600。

### 7.2 蒸馏后的推理脚本仍需显式支持CM

当前推理脚本默认：

```python
use_cm=False
```

因此完成蒸馏后，必须修改推理加载路径和`use_cm=True`，否则仍会使用原始多步DDIM策略。

### 7.3 扩散推理的确定性

当前`deterministic=True`并不完全保证输出一致，因为初始`torch.randn()`仍可能每次重新采样。相同观测重复推理可能产生不同动作，这是当前抖动的重要来源，需要让采样显式使用固定或可控的generator。

### 7.4 真机接触停止

当前推理脚本没有可靠的自动接触检测，仍需要低速、短时、人工急停。后续应加入关节电流/力矩、末端力传感器或视觉接触检测。
