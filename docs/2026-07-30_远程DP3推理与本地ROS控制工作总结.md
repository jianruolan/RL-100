# 2026-07-30 远程 DP3 推理与本地 ROS 控制工作总结

## 1. 完成服务器和本地的整体方案设计

- 确定服务器只负责 DP3 GPU 推理，不运行 ROS，不连接 Piper、CAN 和 RealSense。
- 本地 ROS 负责设备采集、推理通信、动作安全检查和最终控制。
- 本地和服务器之间使用 gRPC，服务器容器通过端口映射或 SSH 隧道提供 `50051`。
- Piper ROS driver 是唯一的 CAN 所有者，其他节点不能再次连接 Piper SDK。

最终结构：

```text
RealSense ROS driver ─┐
                      ├─> 观测/推理 ROS 节点 ──gRPC──> 服务器 DP3
Piper ROS driver ─────┘                                      │
                                                             ↓
                                               动作安全/规划节点
                                                             ↓
                                                    Piper ROS driver
```

## 3. 完成无真机服务器通信工具

- 新增 `tools/local/remote_server_smoke.py`。
- 不需要 ROS、RealSense、Piper 或 CAN，即可测试本机到服务器的完整通信。
- 测试内容包括：


- 服务器准备好后可以直接执行：

```bash

  --server 127.0.0.1:50051
```

## 4. 完成本地 ROS 节点拆分

新增观测和远程推理节点：

```text
tools/local/ros_observation_inference_node.py
```

主要功能：

- 接收 Piper 关节状态；
- 接收 RealSense RGB、Depth 和 CameraInfo；
- 生成 `image[3,84,84]`、`point_cloud[512,3]` 和 `agent_pos[7]`；
- 异步调用服务器 gRPC；
- 发布带序号、时间戳和模型信息的 `[4,7]` action chunk。

新增动作安全和轨迹规划节点：

```text
tools/local/ros_action_planner_node.py
```

主要功能：

- 100 Hz 本地规划；
- 检查动作协议、形状、序号和过期时间；
- 执行关节范围、速度和加速度限制；
- Piper 反馈超时时进入保持；
- 支持 stop 和 estop；
- 通过 `/remote_dp3/joint_cmd` 向 Piper ROS driver 发送命令。

原来的 `tools/local/piper_policy_bridge.py` 保留为直连 SDK 的调试原型。正式运行
Piper ROS driver 时不能同时运行旧 bridge，避免两个进程抢占 CAN。
