## 1. 总体结论

Pico 可以通过 Isaac Teleop 的 CloudXR/WebXR 链路直接遥操作真机 Piper。第一阶段不需要运行 Isaac Sim 或 Isaac Lab。

```text
Pico 控制器
  -> Pico 浏览器 WebXR
  -> CloudXR/WSS/WebRTC
  -> Isaac Teleop ControllersSource
  -> Piper VR Bridge
  -> 坐标转换、clutch、安全过滤
  -> Piper SDK
  -> Piper 真机
  -> Raw HDF5/Zarr
  -> LeRobot / RL-100 Zarr
```

Isaac Sim 可在后续用于 Piper 数字孪生、双臂碰撞检查、仿真数据扩充和真机命令预览，但不是第一批真机采集的前置依赖。

## 2. Isaac Teleop 与 NVIDIA GPU

| 功能 | NVIDIA GPU |
| --- | --- |
| Isaac Sim / Isaac Lab | 需要 |
| Isaac Teleop + CloudXR 实时 Pico 链路 | 官方路径要求 |
| Isaac Teleop 离线 replay | 不一定 |
| Piper SDK 真机控制 | 不需要 |
| 自定义 Pico pose 网络桥接 | 不需要 |
| LeRobot 数据记录 | 不需要 |
| RL-100 模型训练 | 建议使用 CUDA GPU |

当前主机是 NVIDIA Jetson AGX Thor，已经具备 NVIDIA GPU 平台。Jetson 上 `nvidia-smi` 不可用不能单独证明 GPU 不可用；CloudXR 日志已经识别：

```text
NVIDIA Tegra NVIDIA Thor
Vulkan integrated GPU
CUDA context created
```

如果未来不想依赖 NVIDIA/CloudXR，可以改用：

```text
Pico Unity/OpenXR app -> UDP/WebSocket -> Piper Python bridge
```

这条路线不需要 Isaac Teleop 和 NVIDIA GPU，但需要自行开发 Pico 端应用。

## 3. Pico、CloudXR 和网络

### 3.1 连接关系

Pico 不需要 USB 连接 Thor，当前方案通过局域网工作：

```text
Pico 浏览器 -> 局域网 -> Thor CloudXR
```

最简单可靠的方式是让 Pico 和 Thor 连接同一个路由器，并避免访客 Wi-Fi 或 AP 隔离。当前 Thor 地址为：

```text
192.168.212.31
```

Pico 浏览器访问：

```text
https://192.168.212.31:48322/client/
```

### 3.2 浏览器授权

浏览器中的授权包括：

1. 接受 Thor 自签名 HTTPS 证书。
2. 授权网页访问 WebXR 头显和控制器。
3. 建立持续 CloudXR/WebRTC 会话。

连接建立后，控制器数据会持续发送到 Thor：

```text
controller pose, trigger, squeeze, buttons,
tracking-valid, head pose, timestamp
```

Piper 状态、控制命令、三路相机、点云和数据集都可以直接保存在 Thor，不需要经过 Pico 中转。

### 3.3 端口和超时

```text
48322/tcp  Web Client/WSS proxy
49100/tcp  CloudXR backend
47998/udp  CloudXR streaming
```

Piper bridge 必须设置 watchdog：

```text
超过约 100 ms 没有新的 controller 数据 -> Piper hold
```

切换 Thor 网络后，IP 和 WebRTC 候选地址可能变化，建议重启完整 CloudXR launcher，而不是只重用旧 runtime。

检查命令：

```bash
pgrep -af 'isaacteleop.cloudxr|cxr_server|wss' || true
ss -lntup | grep -E '48322|49100|47998' || true
curl -k -I --max-time 5 https://192.168.212.31:48322/client/
```

`HTTP 200` 表示 Web Client 正常。只有 `49100` 而没有 `48322`，说明 runtime 还在但 WSS proxy 已退出。

日志位置：

```text
~/.cloudxr/logs/cxr_server.*.log
~/.cloudxr/logs/wss.*.log
```

启动命令：

```bash
source /home/mtarch/venvs/piper_isaac_teleop/bin/activate
cd /home/mtarch/Desktop/zyf/IsaacTeleop
python -m isaacteleop.cloudxr --accept-eula --host-client
```

## 5. Piper 控制链路

Piper SDK 0.6.1 提供：

```python

GetArmJointMsgs()

```

协议单位：

```text
EndPose X/Y/Z: 0.001 mm

```

控制程序内部应统一使用 meter、radian/quaternion，只有 SDK 边界才转换成协议单位。

```text

```

不要直接采用 Piper 硬件 master/slave 模式，以免 master arm 的控制帧和软件命令冲突。

```text

```

该脚本包含示例 USB 地址，必须先通过 `ethtool -i canX` 确认真实 bus-info 后再修改和执行。

## 6. 坐标系和 clutch

建议定义：

```text
X      XR/OpenXR tracking frame
W      双臂公共 world frame
B_L    左 Piper base frame
B_R    右 Piper base frame
C_L/R  左右 Pico controller frame
E_L/R  左右 TCP frame
```

变换记号：

```text
T_A_B：把B坐标系中的点转换到A坐标系
```

双臂安装关系：

```text
T_W_BL
T_W_BR
```

单臂早期调试可以暂时令 `W = B_L`，但双臂正式采集必须保留公共 world frame，不能简单给右臂坐标取负号。

### 6.1 clutch 变换

按下 squeeze 时记录：

```text
T_X_C0
T_W_E0
```

当前控制器位姿为 `T_X_Ct`：

```text
Delta_T_X = inverse(T_X_C0) * T_X_Ct
Delta_T_W = M_XR_to_W * Delta_T_X * inverse(M_XR_to_W)
T_W_E_target = T_W_E0 * Delta_T_W
```

转到左 Piper base：

```text
T_BL_EL_target = inverse(T_W_BL) * T_W_EL_target
```

右臂同理。

Pico 控制器移动方向必须通过逐轴实验确定，不能复制 xArm/Franka 旧代码中的硬编码矩阵。

### 6.2 单位和姿态约定

```text
quaternion: [x, y, z, w]
position: meter
rotation vector: radian
Piper SDK position: 0.001 mm
Piper SDK rotation: 0.001 degree
```

内部保存 quaternion，发送 Piper 前才转换 Euler；注意 quaternion 顺序、矩阵乘法顺序、米/毫米和弧度/角度混用问题。

## 7. Isaac Teleop 和 RL-100 原代码

Isaac Teleop 的通用实现位于：

```text
../IsaacTeleop/src/retargeters/se3_retargeter.py
```

`Se3AbsRetargeter` 和 `Se3RelRetargeter` 使用 NumPy/SciPy 完成：

- controller 位姿读取。
- 相邻帧旋转差。
- 平移/旋转 scale。
- 平滑和死区。
- 固定姿态/位置 offset。

它们输出 EE pose 或 EE delta，不是通用 IK。

SO-101 clutch 位于：

```text
../IsaacTeleop/src/retargeters/SO101/clutch_retargeter.py
```

主要位置公式：

```text
p_target = p_home + scale * (p_controller - p_controller_origin)
```

RL-100 原有 Vision Pro 遥操作位于：

```text
tools/teleop_off2off_data/teleop.py
```

它通过初始手腕和机器人位姿、手写 `X_VR2Robot`、齐次矩阵和 SciPy Rotation 完成变换，然后调用 xArm/Franka 的 Cartesian servo。该 Python 文件本身没有实现 xArm/Franka IK，IK/轨迹执行由机器人控制器或 vendor driver 负责。

## 8. FK 和 IK 的职责划分

### 8.1 FK

```text
joint position -> TCP pose
```

Piper SDK 本地提供：

```text
piper_sdk/kinematics/piper_fk.py
GetFK(mode="feedback")
GetFK(mode="control")
```

FK 可用于验证 joint/TCP feedback、计算末端状态、后续计算相机动态外参和准备外部 IK。

### 8.2 IK

```text
TCP target -> joint target
```

Isaac Teleop 的 SE(3) retargeter 本身不做通用 IK。SO-101 的真机路径通过 LeRobot `kinematics` 和 URDF 做 IK，相关实现不在当前本地 checkout 中。

Piper SDK 没有发现公开的 Python IK 接口。使用：

```python
MotionCtrl_2(... MOVE P ...)
EndPoseCtrl(...)
```

时，Python 发送 Cartesian target，Piper 控制器/固件负责内部逆解和轨迹执行。因此第一版推荐：

```text
Pico/Isaac SE3
  -> 坐标转换和安全过滤
  -> Piper EndPoseCtrl
  -> Piper 固件内部 IK
```

如果后续需要更强的关节约束、碰撞检查或 IK 可解释性，再引入：

```text
MoveIt 2
Pinocchio + Damped Least Squares
Pink
TRAC-IK/KDL
```

## 9. 数据采集结构

### 9.1 原始数据

保存：

```text
Pico controller pose/buttons/valid/timestamp
Piper joint/TCP/gripper feedback
unfiltered target
safety-filtered target
actual SDK command
episode success/failure/invalid reason
```

三路相机另保存 RGB-D 和设备/主机时间戳。相机标定暂不纳入当前阶段。

### 9.2 训练数据

从 raw 数据派生：

```text
raw -> LeRobot dataset
raw -> RL-100 Zarr
```

单臂 action：

```text
[dx, dy, dz, drx, dry, drz, gripper]
```

双臂 action：

```text
[
  left_dx, left_dy, left_dz, left_drx, left_dry, left_drz, left_gripper,
  right_dx, right_dy, right_dz, right_drx, right_dry, right_drz, right_gripper
]
```

BC action label 使用最终 safety-filtered、实际发送给 Piper 的 command；Pico 原始 pose 和 Piper 实测 TCP delta 单独保存。


```text

```

## 12. 最终路线

```text
Pico 4 Ultra WebXR
  -> Isaac Teleop CloudXR
  -> 自定义 Piper bridge
  -> NumPy + SciPy 坐标转换
  -> Piper SDK FK/TCP feedback 校验
  -> MOVE P + EndPoseCtrl
  -> Piper 固件内部 IK
  -> Raw HDF5/Zarr
  -> LeRobot + RL-100 双格式导出
```

第一阶段不需要 Isaac Sim、Isaac Lab、Piper URDF、MoveIt、Pinocchio IK 或 ROS2。后续增加外部 IK 时，应保持 Pico 输入、坐标约定和数据 schema 不变。
