# 2026-07-20 至 2026-07-21 项目代码、算法与概念理解

本文整理本轮对RL-100、Piper数据、Diffusion policy、VIB、action chunk和一致性蒸馏的理解。

## 1. Piper数据的动作语义

后处理数据中的动作由下一时刻状态构造：

```python
action[t] = state[t+1]
```

训练只使用前六个关节维度，夹爪维度恒定且不参与控制。因此模型输出的是：

```text
t时刻观测 → t+1时刻的六关节绝对目标角
```

不是增量动作。

例如：

```text
当前角度：0.50 rad
模型输出：0.51 rad
```

执行目标应为`0.51 rad`，不能再次计算`0.50+0.51`。

## 2. 训练阶段

RL-100的离线流程可以概括为：

```text
BC Diffusion policy
→ Q/Value critic
→ learned dynamics
→ BPPO/Uni-O4 offline RL
→ 可选Consistency Distillation
```

### BC

使用示教数据拟合动作分布，Diffusion policy通过多步去噪预测动作序列。

### Q/Value

学习离线数据中的价值和动作价值，为offline policy improvement提供评价依据。

### Dynamics

学习动作和观测的转移关系。Piper没有真机或仿真runner时，dynamics可以用于离线rollout，但预测偏差可能影响策略选择。

### Offline RL

使用Q/Value和learned dynamics改进BC策略。没有env_runner时，不能把环境成功率作为best依据，代码会使用dynamics rollout中的`current_mean_qs`作为临时选择依据；它不是实际成功率。

## 3. 图像尺寸和2D/3D策略

### 当前84×84图像链路

现有84数据进入2D R3M时的处理为：

```text
Zarr uint8 84×84
→ 转float并除以255
→ Resize到224×224
→ ImageNet归一化
→ R3M ResNet18
```

上采样不会恢复84×84阶段已经丢失的细节。84×84适合作为跑通流程的基线，但如果方块在画面中很小，原始数据重新处理成160或224更合适。

### 3D策略

当前Piper 3D策略使用：

```text
点云 + 六维关节状态
```

当前3D配置的`backbone: null`意味着图像没有被使用。理论上可以加入图像分支，但现有3D图像编码器存在输入归一化、预训练权重和concat维度问题，不能只切换一个YAML开关后直接复用旧checkpoint。

### 2D策略

2D策略使用：

```text
RGB图像 + 六维关节状态
```

点云字段可保留在数据中，但通过`policy.w_pc=False`忽略。

## 4. VIB结构

当前3D `dp3vib`编码器大致为：

```text
点云512×3
→ PointNet逐点MLP
→ max pooling
→ 64维点云特征

关节状态6维
→ MLP
→ 64维状态特征
```

随后两条分支分别产生：

```text
mu_pc, logvar_pc
mu_state, logvar_state
```

训练时重参数化采样：

```text
z = mu + exp(0.5*logvar)*epsilon
```

推理时使用`mu`，不再随机采样。

当前配置`latent_dim=null`，所以实际上是：

```text
64 → 64
```

VIB没有降低维度，主要作用是随机正则化和KL约束。

开启`use_recon`后，还会从潜变量重建：

```text
512×3点云
6维关节状态
```

总损失大致为：

```text
Diffusion loss
+ beta_kl × KL loss
+ beta_recon × reconstruction loss
```

## 5. `horizon`、`n_obs_steps`和`n_action_steps`

三个参数含义不同：

```text
n_obs_steps     输入历史观测帧数
n_action_steps  最终输出/执行的动作chunk长度
horizon         Diffusion一次生成的完整轨迹窗口长度
```

RL-100主配置的常见默认值是：

```yaml
n_obs_steps: 2
horizon: 5
n_action_steps: 4
no_pre_action: true
```

Piper当前保留三帧历史，因此chunk4应使用：

```yaml
n_obs_steps: 3
n_action_steps: 4
horizon: 6
no_pre_action: true
```

窗口关系为：

```text
horizon = n_obs_steps + n_action_steps - 1
```

`horizon`不等同于chunk长度；当前Piper配置中只是因为窗口关系，数值不同。

## 6. Action chunk执行方式

有两种常见方式。

### Open-loop chunk

模型生成4个动作后连续执行：

```text
推理一次 → 执行a0,a1,a2,a3 → 再推理
```

20 Hz控制下，chunk4覆盖约200 ms，适合模型约5 Hz重新规划。

### Receding-horizon chunk

模型每20 Hz都生成4个动作，但只执行第一个：

```text
预测[a0,a1,a2,a3] → 执行a0
下一周期预测[b0,b1,b2,b3] → 执行b0
```

这种方式需要更多推理计算，但反馈更新频繁，通常更安全。chunk仍能约束模型学习一段时间连续的动作，但后3步不会直接执行。

如果采用receding horizon，当前推理脚本只取第一个动作即可，但必须允许`n_action_steps=4`，不能把模型配置仍写成1。

## 7. 频率、速度与抖动

训练数据采集频率是20 Hz，意味着相邻样本约50 ms。

如果部署为5 Hz：

```text
相邻观测约200 ms
```

三帧历史的时间跨度也从约100 ms变成约400 ms，产生时序分布偏移。模型预测的是约50 ms后的绝对目标，5 Hz下可能表现为停顿、追赶和过冲。

如果模型20 Hz推理并只执行chunk第一个动作，则时序间隔保持一致，通常比5 Hz单步推理稳定。

当前脚本的关节速度限制是：

```text
max_step = max_joint_speed_rad_s / control_rate
```

例如20 Hz、0.15 rad/s：

```text
0.15 / 20 = 0.0075 rad/step
```

速度检查应按实际动作下发频率，而不是策略规划频率。

此外，当前Diffusion采样虽然传入`deterministic=True`，但初始`torch.randn()`仍可能每次重新采样。相同观测可能得到不同动作，这是抖动的重要来源；需要显式固定或管理随机generator。

## 8. 一致性蒸馏

普通Diffusion策略需要多步去噪：

```text
x_T → x_t → ... → x_0
```

一致性模型学习不同噪声等级输入应得到相同最终动作：

```text
f(x_t,t,obs) ≈ f(x_s,s,obs)
```

推理时可以从高噪声直接一步得到动作。

当前配置：

```yaml
num_inference_steps: 10
cm_inference_steps: 1
distill_loss_type: action_same_noise
```

### `after_dp`：BC蒸馏

Teacher是BC的多步Diffusion策略：

```text
latest.ckpt中的BC模型
```

Student是可训练的`distilled_model`。

两者使用同一观测和同一初始噪声，Teacher执行10步DDIM，Student执行1步CM，损失为：

```text
L_cm = || action_student - action_teacher ||²
```

它不是直接拟合数据集动作，而是模仿Teacher的输出。

### `after_offline`：offline best蒸馏

Teacher改为：

```text
best/model.pt + best/encoder.pt
```

其它蒸馏机制类似。

BC蒸馏更接近示教策略，offline best蒸馏更接近offline RL策略；后者可能有更高价值，也可能继承Q/dynamics偏差。

## 9. 真机部署注意事项

推理时输出仍然是绝对关节目标。每个目标发送前都要检查：

```text
Piper物理关节限位
训练动作范围
单周期最大关节变化
关节状态是否过期
点云是否出现大量飞点
推理/控制循环是否超时
人工急停和接触停止
```

当前任务没有可靠自动接触检测，首次部署必须：

```text
低速度、短时、shadow先行、操作者始终可触达急停
```

一致性蒸馏只能降低推理耗时，不能替代接触检测、动作限速和真机安全策略。
