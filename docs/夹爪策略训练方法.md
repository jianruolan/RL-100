# Pico-Piper 夹爪策略训练方法

## 1. 文档目的

本文档说明当前 Pico 4 Ultra + Piper 遥操作项目中夹爪策略的数据来源、标签定义、模型训练、事件解码和离线测试方法。目标是让策略学会：

> 根据 RGB-D、机械臂姿态和当前夹爪状态，判断何时应该发出闭合或打开意图，而不是简单复制当前夹爪状态。

本文描述的策略只生成离线动作建议，不包含 Piper SDK 调用、机械臂使能或自动下发命令。当前结果适用于离线回放和 shadow mode，不代表已经可以绕过限位、watchdog、急停或人工监督直接控制真机。

## 2. 原始问题与根因

旧版本夹爪标签来自 `/piper_teleop/gripper/position` 的测量宽度。模型输入中同时包含当前夹爪宽度，而 action chunk 的第一个夹爪目标又是当前时刻的宽度状态。因此模型很容易学习以下恒等映射：

```text
当前打开  -> 预测打开
当前闭合  -> 预测闭合
```

旧数据并不是缺少闭合状态：打开帧约占 57%，闭合帧约占 43%。真正稀少的是状态转换事件。24 条成功轨迹通常各有一次闭合和一次打开，相对于数千个状态保持帧，开合事件只占很小比例。

此外，测量宽度是命令执行后的反馈：

```text
操作者按下 Close
        ↓
控制器发送闭合命令
        ↓
夹爪开始运动
        ↓
宽度反馈变为闭合
```

如果用最后一步的宽度反馈作为操作意图标签，标签天然晚于操作者的真实决策。模型可能准确识别“已经闭合”，却无法学习“现在应该开始闭合”。

因此本轮修复围绕四点展开：

1. 使用操作者实际发出的开合命令生成标签。
2. 预测未来状态，避免监督当前状态。
3. 提高状态转换邻域的训练权重。
4. 在线侧用迟滞、连续确认和状态锁存把概率转换成离散事件。

## 3. 数据来源与转换

### 3.1 使用的 ROS Topic

夹爪训练主要使用以下数据：

| Topic | 用途 |
|---|---|
| `/piper_camera/d435i/color/image_raw` | RGB 视觉输入和主时间轴 |
| `/piper_camera/d435i/depth/image_rect_raw` | 深度和深度有效掩码 |
| `/joint_states` | 当前 6 维关节反馈 |
| `/piper_teleop/status` | 实际下发的关节命令和安全状态 |
| `/piper_teleop/gripper/position` | 当前夹爪宽度反馈，仅作本体输入和反馈评估 |
| `/piper_teleop/pico_frame` | `gripperOpen/gripperClose` 操作者命令，作为夹爪标签来源 |

转换代码位于 `extract_rosbags.py`。

### 3.2 命令状态机

`gripperOpen` 和 `gripperClose` 是持续时间较短的手柄按键脉冲，而 RGB 相机和 Pico 控制帧频率不同。转换器不会只取距离 RGB 最近的一条 Pico 消息，而是汇总相邻两帧 RGB 之间的全部 Pico 消息，防止短脉冲被漏掉。

状态更新规则为：

```text
收到 gripperClose=true -> desired_open = 0
收到 gripperOpen=true  -> desired_open = 1
没有新命令              -> 保持上一期望状态
```

每条 episode 的初始 `desired_open` 由第一帧测量宽度初始化。当前数据中闭合宽度残余约为 0.05 m，张开宽度约为 0.07 m，因此仅在初始化和反馈评估时使用 0.061 m 阈值：

```text
feedback_open = gripper_width_m >= 0.061
```

训练标签本身不再由这个阈值生成。

### 3.3 保存的夹爪字段

转换后的 NPZ/HDF5 包含：

| 字段 | 类型 | 含义 |
|---|---|---|
| `gripper_width_m` | float32 | 夹爪测量宽度 |
| `gripper_command_state` | uint8 | 锁存后的期望状态，1=张开，0=闭合 |
| `gripper_open_event` | uint8 | 当前相机间隔内是否出现打开命令 |
| `gripper_close_event` | uint8 | 当前相机间隔内是否出现闭合命令 |

转换过程同时修复了旧版本中的 RGB-D 对齐问题。旧代码错误地保存了未经对齐的完整 Depth 流，可能出现 271 帧 RGB 对应 289 帧 Depth。当前版本保存的是逐 RGB 时间戳选出的 `aligned_depth`，所有 episode 的 RGB、Depth、状态和控制数组长度一致。

### 3.4 当前数据规模

数据集文件为：

```text
imitation_learning/pico_bc_commands.h5
```

当前统计：

- 成功 episode：24 条
- 总相机帧：7392
- 保留训练样本：5596
- 每条 episode 的期望夹爪状态转换：2 次
- 失败 episode：不进入行为克隆训练

## 4. 数据划分

划分以 episode 为单位，不允许把同一条轨迹的不同帧同时放入训练集和测试集。这样可以避免相邻画面泄漏造成虚高结果。

当前配置：

```text
随机种子：42
训练集：17 episodes
验证集：3 episodes
测试集：4 episodes
```

验证集用于选择检查点和夹爪事件解码参数；测试集在参数确定后才用于最终评估。

具体列表保存在：

```text
imitation_learning/runs/bc_resnet18_chunk12_commands/split.json
```

## 5. 模型输入与输出

### 5.1 输入

单个时间步输入由视觉和本体状态组成。

视觉输入是 5 通道张量：

```text
[R, G, B, normalized_depth, depth_valid_mask]
```

- RGB 分辨率：192 × 256
- Depth 裁剪范围：0.15～1.0 m
- 无效深度被置零，并由独立有效掩码表达
- 训练增强只使用轻微颜色和对比度扰动
- 不做水平翻转、几何裁剪等会改变机器人空间关系的增强

本体输入是 7 维：

```text
[6维归一化关节反馈, 当前夹爪宽度/0.07]
```

保留当前夹爪状态并不是问题。它能帮助控制器判断是否需要重复命令。需要避免的是把当前状态同时直接当成第一个监督目标。

### 5.2 视觉骨干和融合层

- 视觉骨干：ImageNet 预训练 ResNet-18
- 首层卷积：由 3 通道扩展为 5 通道
- Depth 卷积权重：由 RGB 权重均值初始化
- Depth 有效掩码权重：初始化为零
- 本体编码器：两层 MLP
- 融合隐藏维度：512
- Dropout：0.1

### 5.3 输出

模型输出一个 12 步 action chunk：

1. `12 × 6` 的归一化关节增量。
2. `12` 个夹爪期望张开 logit。

夹爪概率语义必须保持一致：

```text
p_open  = sigmoid(gripper_logit)
p_close = 1 - p_open
```

不能把 `p_open` 直接解释为闭合概率。

## 6. 未来夹爪监督

### 6.1 标签时间偏移

关节 action chunk 仍从当前索引 `i` 开始：

```text
joint targets = [i, i+1, ..., i+11]
```

夹爪目标从未来第 3 个相机步开始：

```text
gripper targets = [i+3, i+4, ..., i+14]
```

即：

```text
gripper_future_offset = 3
```

这样，第 0 个夹爪输出不再监督当前夹爪状态，而是监督未来约 3 个相机步之后的操作者期望状态。模型必须结合视觉、机械臂姿态和运动阶段判断是否即将发生闭合或打开。

### 6.2 事件邻域加权

普通的 open/closed 类别加权不能解决转换事件稀少的问题，因为打开和闭合状态本身并不严重失衡。当前实现直接对命令事件附近的监督位置加权：

```text
事件半径：±2 帧
事件邻域权重：10
普通状态保持帧权重：1
```

设第 `k` 个夹爪目标的 BCE 为 `BCE_k`，事件权重为 `w_k`，有效 padding mask 为 `m_k`，则：

```text
L_gripper = sum(BCE_k × w_k × m_k) / sum(w_k × m_k)
```

旧版本按 batch 动态计算 open/closed 的 `pos_weight`，但正类实际表示张开，与注释中的“稀有闭合命令”相反。当前实现已经移除这项容易混淆的状态类别加权。

## 7. 总训练损失

总损失为：

```text
L = L_joint_huber + L_gripper_weighted_bce + 0.01 × L_action_smooth
```

其中：

- `L_joint_huber`：归一化关节增量的 Huber loss。
- `L_gripper_weighted_bce`：带事件邻域权重的期望状态 BCE。
- `L_action_smooth`：相邻预测关节动作之间的轻量平滑约束。

所有 chunk 末尾的补齐位置均由 padding mask 排除。

## 9. 从概率到开合事件

模型输出的是未来期望状态概率，而不是应当每帧重复发送的电机命令。`gripper_control.py` 使用状态锁存器把概率块转换为一次性事件。

验证集校准得到的当前参数为：

```text
close_threshold = 0.4
open_threshold = 0.6
consecutive = 2
cooldown_frames = 4
window_start = 0
window_end = 8
```

每次推理取预测 chunk 前 8 步的平均张开概率：

```text
score = mean(p_open[0:8])
```

当前夹爪被锁存为张开时：

```text
score < 0.4，且连续出现2次 -> 产生一次 close 事件
```

当前夹爪被锁存为闭合时：

```text
score > 0.6，且连续出现2次 -> 产生一次 open 事件
```

事件触发后：

1. 更新锁存状态。
2. 进入 4 帧冷却期。
3. 不重复发出同类型命令，直到预测到相反状态。

0.4/0.6 构成迟滞区间，可以降低概率在 0.5 附近波动时反复开合的风险。至少连续两帧确认是硬约束；评估参数搜索不会接受单帧触发方案。

## 10. 真实数据测试方法

测试脚本为 `evaluate_gripper_events.py`。它不会连接 ROS 控制节点，也不会向 Piper 发送命令。

测试步骤：

1. 加载最佳模型检查点。
2. 对验证集和测试集的真实记录 RGB-D 帧逐帧推理。
3. 仅在数据中的有效 sample mask 上更新夹爪状态机。
4. 在验证集搜索阈值、连续确认次数和预测窗口。
5. 固定参数后回放完全隔离的 4 条测试轨迹。
6. 对比模型事件、操作者命令事件以及夹爪宽度反馈变化。

事件匹配容差为 12 个相机帧。评估指标包括：

- close event recall
- open event recall
- event precision / recall / F1
- false event count
- missed event count
- 事件时序误差
- 预测状态轨迹准确率
- 命令到宽度反馈发生变化的延迟

整体帧级 F1 不能替代这些事件指标。即使模型在大量保持状态帧上全部正确，只要没有产生闭合事件，策略仍然无法完成抓取。

## 14. 真机接入前的后续工作

当前离线结果证明模型能够在记录数据中产生夹爪状态转换，但至少还需要完成以下步骤：

1. **实时 shadow mode**：模型接收真机相机和状态，但只记录建议，不发送命令。
2. **统计提前/延后触发**：重点复查 episode 000023 类似的提前闭合问题。
3. **增加安全门控**：只有末端进入允许抓取区域、速度足够低且机械臂状态正常时才允许 close。
4. **加入命令超时**：推理超时、图像过期、状态过期或通信断线时不产生新事件。
5. **人工确认急停链路**：策略不能绕过现有使能、关节限位、速度限制、watchdog 和物理急停。
6. **扩大数据覆盖**：增加光照变化、方块位置小扰动、抓取失败、重新对准和干扰物场景。
7. **独立真实闭环评估**：统计抓取成功率、错误闭合次数、物体掉落率和单次任务最大风险动作。

只有 shadow mode 和低速闭环测试均通过后，才能逐步允许夹爪事件进入实际执行链路。
